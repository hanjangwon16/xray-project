# CT·X-ray·초음파·해부 아틀라스: 자료 확보와 시뮬레이터 개발안

2026-10-15 조사. 이 문서는 확보한 자료의 용도와 다음 구현 제안이다. 시뮬레이터 구현 완료나 임상 정확도 검증을 뜻하지 않는다.

## 핵심 방향

사용자는 먼저 인체에서 구조를 고른다. 같은 화면에서 CT 절단면, X-ray 빔, 초음파 탐촉자를 움직이며 결과와 원인을 함께 본다. 아틀라스 학습과 촬영 연습을 연결하되, 서로 다른 환자의 영상을 같은 사람에게서 생성된 것처럼 합치지 않는다.

서비스는 기존 웹 앱을 확장한다. 원본 다운로드·변환·고품질 기준 영상 생성은 로컬 Python에서 수행한다. 첫 단계는 추가 GPU 서버 없이 가능한 CT/DRR·팬텀 초음파 연동이며, GPU 초음파 엔진은 별도 실행 가능성을 검증할 후보로 둔다.

## 3. 영상 종류별로 가능한 시뮬레이션

| 모드 | 입력 | 사용자가 조절 | 결과와 경계 |
|---|---|---|---|
| 해부 아틀라스 | BodyParts3D 메시·구조 ID·용어 | 구조 선택, 계통, 투명도, 회전·확대 | 위치·관계·이름 학습. 실제 CT 없는 부위는 제공 범위를 표시 |
| CT 단면 | 같은 환자의 HU 볼륨·분할·방향행렬 | 단면 위치, 직교/사위면, W/L | 실제 볼륨 리슬라이스. 관전압·선량·재구성 알고리즘을 변경한 실제 CT 획득 시뮬레이터와는 구분 |
| X-ray 촬영 | CT HU 볼륨·감쇠 모델·소스/검출기 | 환자 자세, 빔 각도, 중심선, 조사야, 거리 | CT에서 계산한 DRR. 실제 획득 X-ray는 별도 사례로 표시 |
| 초음파 사례 | 실제 2D 이미지 또는 cine와 주석 | 영상/클립 선택, 재생, 경계·이름 표시 | 실제 영상 학습. 공간 추적 없는 프레임을 탐촉자 위치에 임의 배정하지 않음 |
| 초음파 볼륨 탐색 | 3DUS 볼륨·spacing·probe/world 변환 | 볼륨 안 절단면과 표시 깊이 | 측정된 볼륨의 자유 단면 탐색. 새 각도의 반사·음영·압박을 재현하는 것은 아님 |

CT HU를 회색으로 바꾸고 노이즈만 더해서 초음파라고 부르지 않는다. 정지영상에 회전 애니메이션만 붙여 공간 시뮬레이터라고 부르지 않는다.

## 4. 화면: 인체에서 시작하는 한 화면

1. 상단에 `아틀라스 / CT / X-ray / 초음파`, 부위·사례·실제/합성 상태를 고정한다.
2. 중앙 왼쪽은 전신 3D이며 뼈·장기·혈관·신경·근육을 단독/조합 선택한다. 선택 구조와 주변 구조를 구분한다.
3. 오른쪽은 현재 모드의 큰 영상 하나다. 구조를 누르면 이름과 지원 촬영 사례가 나타난다. 같은 환자가 아니면 별도 비교 사례로 이동했음을 명시한다.
4. CT에서는 절단면을 3D 몸 안에 표시하고, 양쪽 영상의 좌표를 동일 환자 좌표로 연동한다.
5. X-ray에서는 소스→인체→검출기와 조사야를 표시한다. 각도를 바꾸면 어떤 뼈가 겹치는지 색상 학습 overlay와 원영상 전환으로 설명한다.
6. 초음파에서는 피부 접촉점, 탐촉자 방향 표시, 스캔 부채꼴/평면을 함께 보여준다. `이동 / 회전 / 기울임 / 흔들기` 조작을 구분하고 초기 위치 복귀를 제공한다.
7. 아래 컨트롤은 현재 모드에 필요한 것만 표시한다. 100dvh 화면에서 페이지 스크롤 없이 동작하고 작은 화면 도구는 접어서 선택한다.
8. 범위 밖은 검은 영상에 임의 장기를 띄우지 않고 지원 범위와 복귀 동작을 표시한다.

## 5. 공통 데이터 계약 제안

새 사례 manifest는 다음 정보를 분리한다. 기존 manifest에 즉시 강제 적용하지 않고 변환기를 먼저 만든다.

- 정체성: `caseId`, `subjectId`, `region`, `modality`, `sourceKind`(실제 정지/실제 cine/실제 볼륨/합성), `sourceUrl`, `license`, `citation`, `changes`.
- 좌표: 단위 mm, 환자 RAS 좌표, voxel-to-world 4×4 행렬, spacing·dimensions. DICOM LPS 입력은 명시적으로 변환하고 행렬을 보존한다.
- 정합: 영상별 native 좌표, 공통 subject 좌표로 가는 별도 행렬, 정합 방법·검수 상태·잔여 오차. 같은 subject라도 정합 확인 없이 픽셀 좌표를 공유하지 않는다.
- 분할: 실제 클래스 ID, 구조의 영문/한글명·FMA 대응, 생성 방법, 검수 상태. 생성된 분할을 전문가 정답으로 표시하지 않는다.
- 가용 범위: volume bounds, 제공 장기, 완전성, 빠진 계통. 아틀라스 형상과 특정 환자 CT를 별도 엔티티로 둔다.
- 초음파: probe-to-world, image-to-probe, linear/curvilinear 형상, 좌우 marker 규약, 깊이, scanline 정보, 추적/보정 정보 존재 여부.
- 자산: 바이트 수·SHA-256, 원본 크기·리샘플 크기, 압축과 dtype, 배포 가능한 파생물 목록.

## 6. 도구 선정과 역할

- **사용자 제품:** 기존 React·TypeScript·vtk.js 웹 앱 유지. 초기 버전에서 별도 앱 설치를 요구하지 않는다.
- **CT/메시 검수:** 3D Slicer. 단면·분할·방향과 landmark를 확인한다. PLUS 예제 연동을 시험할 때는 SlicerIGT/PLUS 실행 환경을 별도로 준비한다. 이번에 도구를 설치하거나 PLUS 엔진을 실행한 것은 아니다.
- **전처리:** 기존 Python/NIfTI 파이프라인 확장. 영상과 mask resampling을 구분하며 mask는 최근접 보간을 사용한다.
- **X-ray 기준:** 기존 DRR worker를 먼저 팬텀으로 검증하고 DiffDRR와 동일 geometry로 비교한다. GPU 엔진 교체 전 좌표·고정 대비·경로 길이를 해결한다.
- **초음파 첫 실험:** 확보한 PLUS 팬텀 볼륨을 리슬라이스하고, 별도로 메시/물성 기반 scanline 근사를 구현 가능성 검증한다. PLUS는 감쇠·흡수·입사각 반사·speckle을 포함하는 단순 모델이며 모든 음향 현상을 재현하지 않는다.
- **오프라인 음향 실험:** PyMUST. 표준 점 산란체·낭종·경계 팬텀에서 파라미터 변화 방향을 비교한다. 브라우저 실시간 엔진으로 그대로 탑재한다고 가정하지 않는다.
- **GPU 확장 후보:** 확보한 Isaac 엔진은 CUDA 12.6+, NVIDIA driver 555+, OptiX SDK 8.1을 요구한다. Mac의 기본 경로로 채택하지 않는다. 필요하면 별도 NVIDIA 서버에서 성능·비용을 측정한 뒤 결정한다.
- **배포:** 작은 웹 파생자산만 기존 정적 배포에 포함한다. 원본 수백 MB/GB ZIP은 로컬 연구용으로 보존한다. 대규모 사례가 필요해질 때만 object storage/CDN을 추가 검토한다.

## 7. 구현 작업 순서와 완료 기준

### A. 원본·출처 정리
소유: `data/sources/*`, `scripts/fetch_imaging_sources.py`, 후속 사례 변환 스크립트.
- 원본 ZIP·제공처 메타데이터·코드 commit·LICENSE를 보존한다.
- 원본 영상 수와 마스크 연결, 중복·메타데이터 누락을 확인한다. 출처의 전체 수와 ZIP 내부 문서용 이미지 수를 혼동하지 않는다.
- X-ray 촬영 자세/거리/관전압이 없는 사례는 unknown으로 두고 추정값을 정답으로 만들지 않는다.
- 완료: 제공처 MD5·로컬 SHA-256·크기·ZIP CRC 통과, 사례별 출처를 역추적 가능.

### B. 기존 학습 흐름 먼저 복구
소유: `AtlasView.tsx`, `korean.ts`, `AnatomyPreview.tsx`, 해당 동작 검증.
- 퀴즈 이벤트가 최초 상태를 참조하는 문제를 재현하고 정답 클릭·오답·다음 문제까지 확인한다.
- 한글 정규식 때문에 이름이 뼈/간 등으로 축약되는 문제는 구조 ID별 용어표와 원문 병기로 개선한다.
- 선택 구조로 카메라 focus, 실제 사례 지원 여부와 좌우/전후 표식을 분명히 한다.
- 완료: 사용자가 구조를 찾아 선택하고 실제로 채점·피드백을 받음. 첫 화면 노출만 검사하지 않음.

### C. CT와 X-ray의 공간 연결
소유: `App.tsx`, `beam.ts`, `drr.worker.ts`, 새 공통 좌표 모듈.
- 환자 좌표·projection basis를 공통화한다. AP/PA/좌우측면 및 비대칭 marker로 좌우 반전을 검증한다.
- SOD/SDD/OID와 조사야를 구분하고 프레임마다 변하는 자동 min/max 대비를 고정 비교 가능한 방식으로 바꾼다.
- 동일 CT 분할의 선택 구조를 CT 위치와 투영 경로에 연결한다. 여러 장기가 한 픽셀에 중첩됨을 설명한다.
- 완료: 균일 팬텀 경로 길이·대칭·확대율 수치 검사와 동일 geometry 기준 DRR 비교. 현재 복부 CT를 전신 CT로 표기하지 않음.

### D. 초음파 공간 조작의 최소 증명
소유 제안: `UltrasoundView.tsx`, probe pose 모듈, US volume loader.
- 먼저 사람 대신 확보한 팬텀 3DUS를 사용한다. 이미지 방향행렬·원시 추적 transform·calibration 존재 여부를 확인한다.
- 실제 추적과 보정 정보가 부족하면 `볼륨 단면 탐색`으로 한정한다. 마우스 조작을 실제 탐촉자와 일치한다고 주장하지 않는다.
- 팬텀 표면의 접촉점과 스캔면을 보여주고, probe 이동에 따라 같은 좌표의 단면이 바뀌게 한다.
- 완료: 알려진 landmark 위치가 단면과 3D에서 일치. 이동·회전·깊이 변화·초기화·범위 밖 처리를 실제 조작 확인.

### E. 인체 초음파로 확장
소유 제안: 음향 물성표, US 합성 worker/renderer, 부위별 사례 manifest.
- 장기 메시 외에 피부·피하지방·뼈·공기 등 빔 경로의 매질을 포함한다. 누락된 매질은 알려진 한계로 표시한다.
- 반사·감쇠·음영·후방 증강을 단계별 팬텀에서 확인한다. speckle seed를 공간에 고정해 조작할 때 매 프레임 노이즈가 튀지 않게 한다.
- linear/curvilinear probe를 분리한다. gain은 표시 신호 조절이고 실제 보이지 않는 구조를 생성하지 않는다. 압박·호흡·혈류 Doppler는 별도 물리 검증 전 제공 완료로 표시하지 않는다.
- TRUSTED를 사용할 수 있게 되면 같은 환자 CT와 3DUS를 정합해 신장부터 비교한다. BUS-BRA를 복부 CT에 억지로 대응시키지 않는다.
- 완료: 실제 영상과 합성의 차이를 공개하고 교육자가 구조·방향·대표 artifact를 검토. 검토 전에는 유료 임상 수준으로 홍보하지 않음.

### F. 돈을 내고 쓸 이유를 검증
소유 제안: 학습 과제·피드백·진도 저장, 사용성 검증 기록.
- 자유 탐색 옆에 `목표 구조 찾기 → 촬영면/각도 예상 → 조작 → 결과와 원인 확인 → 다시 시도`의 짧은 과제를 둔다.
- CT는 단면 방향과 장기 위치, X-ray는 중첩과 조사야, US는 marker 방향과 장축/단축 등 실제 제공 데이터로 설명 가능한 과제부터 만든다.
- 진도 저장은 우선 개인 브라우저에서 가능하도록 제안한다. 계정/유료 결제/기관 대시보드는 별도 결정이며 이번 자료 수집 범위에 넣지 않는다.
- 완료: 대상 학습자가 도움 없이 과제를 끝내고 왜 결과가 달라졌는지 설명할 수 있는지 관찰. 시각적 화려함만으로 상용 가치 검증을 대신하지 않는다.

## 8. 검증과 보고 규칙

현재 수집 검증: `python3 scripts/fetch_imaging_sources.py --verify-only`. 해시가 다른 기존 파일을 자동 덮어쓰지 않는다. 미완료 다운로드는 `.part`로 남고 성공 자산으로 세지 않는다.

후속 구현은 TypeScript/Vite build, 해당 조작 시나리오, 좌표·팬텀 수치 검증만 우선 수행한다. 기존 smoke test 통과를 임상 정확도 증명으로 사용하지 않는다. 임상 영상의 텍스트·식별정보와 재배포 범위를 배포 전 실제 표본에서 검수한다.

다음 구현은 사용자 지침의 dryforge ready 절차에서 상세 동작과 승인 가능한 작업 명세로 확정한 뒤 go로 진행한다. 현재 문서는 그 전의 조사·개발 제안이며 승인된 전체 기능 명세로 취급하지 않는다. 이번 변경은 자료 수집과 문서·검증 도구이며 서비스 배포를 변경하지 않는다.

## 9. 이번 확보·검증 실측

- 원본 데이터·PLUS 예제·코드 스냅샷 12개 자산, 합계 **498,728,856바이트**(약 499MB, 메타데이터·추출한 LICENSE 별도).
- 제공처 MD5가 있는 두 데이터 ZIP은 MD5·크기를 확인했다. 12개 자산 모두 로컬 SHA-256 재검증에 통과했다. 네 ZIP의 전체 멤버 CRC 검사 오류 없음.
- BUS-BRA: 실제 영상 PNG **1,875장**, 대응 mask PNG **1,875장**. ZIP 내부 LICENSE.txt는 허용적 자체 문구와 인용·고지 보존 의무를 담고 있다. Zenodo CC BY 4.0 메타데이터와 함께 보존한다.
- FracAtlas: dataset.csv **4,083행**, JPEG 파일 경로 **4,085개**. `IMG0003375.jpg`, `IMG0003376.jpg`가 Fractured/Non_fractured 양쪽에 존재한다. CSV 밖의 새 사례 2개가 아니다. 후속 변환에서 이 두 ID는 검수 대기 상태로 제외하고 분류·해시·주석 충돌을 확인한다.
- PLUS 재구성 영상: 압축 해제 후 **1,620,528바이트 = 147×106×104 uint8 voxel**, spacing 0.5mm. 이는 팬텀이지 인체 자료가 아니다.
- TRUSTED: 원본 ZIP을 통째로 받지 않았다. 중앙 디렉터리와 README·DUA만 부분 요청으로 조회했다. `data/sources/trusted/`에 사용 조건 문서 보존. 서명하거나 이메일을 보내지 않았다.
- 상세 관측: `data/sources/verification.json`. 이 검사는 다운로드 완전성 검사이며 모든 영상의 해부학·진단 정답이나 시뮬레이터 정확도를 검증한 것이 아니다.
